# Health Chat and Clinics repair

Production diagnosis: Health Chat returned `ok:false` because `OPENROUTER_API_KEY` was missing. The diet feature has its own fallback and was left unchanged. Clinics returned HTTP 503 after all original Overpass mirrors failed.

## Changes
- Health Chat now supplies clearly labelled, limited, prewritten basic guidance when OpenRouter is unavailable. It does not impersonate a live AI model. Online model behavior is preserved when the provider is configured.
- The reply includes its mode, a visible limitation notice, and an NHS source where applicable. No drug doses or diagnoses are generated by the basic guide.
- Chat completion runs in a worker thread, avoiding blocking other API requests.
- Clinics uses updated Overpass mirrors, indexed bounding-box queries, exact-distance filtering, a bounded 10-minute cache, and rejects incomplete upstream replies.
- Facilities without coordinates are skipped instead of being assigned the user's location.
- A user-selected city/postal-code search works without browser location permission. City coordinates are approximate centers. The UI identifies this limitation.
- Clinic, hospital and pharmacy Google Maps search links remain usable when the directory provider is unavailable. These open external listings; they are not fabricated in-app clinic results.

## Remaining configuration
Full online Health Chat still requires a valid server-side `OPENROUTER_API_KEY`. Store it in the backend service's production environment and redeploy; never commit it or expose it as a `VITE_` variable. The connected Vercel account did not expose this project's team, so no secret was added during this repair.

## Validation
23 backend tests passed, including existing fracture tests and the new chat/clinic cases. TypeScript and the frontend production build passed. Live release checks are performed after deployment.
