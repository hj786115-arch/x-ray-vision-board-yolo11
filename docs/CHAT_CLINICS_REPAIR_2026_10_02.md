# Health Chat and Clinics repair

Production diagnosis: Health Chat returned `ok:false` because `OPENROUTER_API_KEY` was missing. The diet feature has its own fallback and was left unchanged. Clinics returned HTTP 503 after all original Overpass mirrors failed.

## Changes
- Health Chat now supplies clearly labelled, limited, prewritten basic guidance when OpenRouter is unavailable. It does not impersonate a live AI model. Online model behavior is preserved when the provider is configured.
- The reply includes its mode, a visible limitation notice, and an NHS source where applicable. No drug doses or diagnoses are generated by the basic guide.
- Chat completion runs in a worker thread, avoiding blocking other API requests.
- Clinics uses updated Overpass mirrors, indexed bounding-box queries, exact-distance filtering, a bounded 10-minute cache, and rejects incomplete upstream replies.
- Facilities without coordinates are skipped instead of being assigned the user's location.
- A user-selected city/postal-code search works without browser location permission. City coordinates are approximate centers. The UI identifies this limitation.
- Clinic, hospital and pharmacy Google Maps search links remain usable when the directory provider is unavailable. These open external listings; they are not fabricated in-app clinic results.

## Remaining configuration
Full online Health Chat still requires a valid server-side `OPENROUTER_API_KEY`. Store it in the backend service's production environment and redeploy; never commit it or expose it as a `VITE_` variable. The connected Vercel account did not expose this project's team, so no secret was added during this repair.

## Validation
23 backend tests passed, including existing fracture tests and the new chat/clinic cases. TypeScript and the frontend production build passed. Live release checks are performed after deployment.

## Follow-up repair
- Nearby healthcare now uses one category-filtered Photon reverse lookup with the requested GPS coordinates and radius. Responses are cached for 10 minutes and filtered/sorted by exact distance. Lahore and Karachi live provider checks returned 50 named listings each in about 9 seconds.
- Overpass remains a fallback; its request now includes node coordinates (`out body center`) rather than tags-only output, and uses GET for the compact read-only query.
- Health Chat accepts an optional server-only `HEALTH_CHAT_API_KEY` containing an OpenRouter API key. This enables chat without changing the shared key used by the working diet planner or scan synthesis. `HEALTH_CHAT_MODEL` defaults to `qwen/qwen3.8-27b:free`, with `google/gemma-4-31b-it:free` as a configured free fallback.
- English and Urdu prompts explicitly follow the latest question and topic changes. Actual AI verification still requires an authenticated OpenRouter account and a configured key.
- Photon is a named-place search service, not an exhaustive medical directory. Existing Maps buttons remain available.
- Provider reference: https://github.com/komoot/photon/blob/master/docs/api-v1.md

- Live activation verified the key, but the unrestricted free router returned reasoning-only output on one test and poor Urdu on another. Health Chat now uses the specific free multilingual model chain above with thinking disabled, rejects reasoning-only completions, and strips marked thinking blocks. These strict completion rules are opt-in for Health Chat; existing diet/scan callers retain their behavior.
- Production subsequently returned a Qwen upstream shared-pool HTTP 429 on all three attempts despite the model list. Health Chat now explicitly selects its backup on retry instead of repeatedly calling that rate-limited primary. Existing shared callers keep their original routing. This reduces provider-specific failures but cannot remove free-tier quotas or simultaneous outages.
